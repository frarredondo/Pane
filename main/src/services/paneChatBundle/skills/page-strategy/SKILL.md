# Page strategy

Use this skill before drafting a page. Decide which page deserves to exist,
what it must accomplish for the searcher, and how the product can appear while
the answer stays intact.

Core rule: promotion belongs only where it helps the searcher's job-to-be-done.
If the page would collapse with the CTAs removed, the strategy is weak.

## Inputs to gather

- Target keyword, query, or topic cluster.
- Business goal and desired conversion, if any.
- The product, category, or offer being connected to the query.
- Audience and buying stage.
- Current SERP notes, competitor examples, or pages the user admires or
  dislikes.
- Constraints: brand voice, allowed claims, available proof, and available
  screenshots, data, or examples.

When key inputs are missing, make reasonable assumptions and label them. Ask
only when the answer changes the page type, product role, or risk profile.

## Workflow

1. Classify the searcher job and the dominant and secondary intents. Load
   [intent-and-searcher-job.md](references/intent-and-searcher-job.md).
2. Decide whether this brand should publish the page. Load
   [product-fit-permission.md](references/product-fit-permission.md).
3. Pick the page type, answer shape, and expected comparison set.
4. Set the time-to-value bar. Load
   [time-to-value.md](references/time-to-value.md).
5. Define the proof and E-E-A-T requirements: firsthand use, screenshots, data,
   expert input, citations, examples, pricing, limitations, or methodology.
6. Define the product role and CTA boundaries: lead, contextual, related, light
   mention, or exclude.
7. Draft the page brief, using the structure in
   [page-strategy-workflow.md](references/page-strategy-workflow.md).
8. For a listicle, comparison, alternatives page, or product-led informational
   page, calibrate against
   [good-vs-bad-examples.md](references/good-vs-bad-examples.md).

## Output format

Return a practical page brief:

- Page thesis
- Target query and intent map
- Audience and job-to-be-done
- Recommended page type
- Time-to-value requirement
- Product-fit permission and CTA boundary
- Required proof and E-E-A-T
- Recommended structure
- SERP differentiation angle
- What to leave out
- Risks before writing
- Handoff notes for `page-review`

## Handoffs

- Use the `page-review` skill once a draft exists.
- Use the `site-content-audit` skill when the question involves many URLs, a
  sitemap, a traffic decline, a competitor teardown, or pruning and merging
  decisions.
